# quality-rubric.md: judge 채점 루브릭 (8기준 16점) v0.1

> 코드로 잡기 어려운 **주관적 품질**을 모델(judge)이 채점하는 기준.
> judge는 가능하면 작성자와 **다른 컨텍스트의 critic**(서브에이전트)이 맡는다.
> 자기 초안을 스스로 채점할 때 생기는 관대화(self-preferential bias)를 막기 위해서다.
> 단일 컨텍스트 모드에서는 "비평가 모자"를 쓰고 채점하되 #8을 후하게 주지 않는다.

## 채점 기준 (각 0·1·2점, 합 16점 만점)

| # | 기준 | 0점 | 1점 | 2점 |
|---|------|-----|-----|-----|
| 1 | **KEY MESSAGE 완결성** | 명제 없음/단어 나열 | 있으나 모호 | 데이터를 관통하는 한 줄 통찰(40~100자) |
| 2 | **근거·로직** | 주장만 | 근거 일부 | 모든 주장에 수치·사례·출처 연결 |
| 3 | **문체 일관성** | 개조식·격식 혼재 | 일부 이탈 | 목적 문체로 완결(보고서면 격식 산문 3~4단락) |
| 4 | **쉬운 전달(비유·예시)** | 전문용어 나열 | 예시 빈약 | 비전문가도 이해할 예시+전문성 양립 |
| 5 | **객관성(과장 배제)** | 화려한 형용사 다수 | 일부 | 객관·중립 서술 |
| 6 | **유기적 연결** | 단락 단절 | 느슨 | 하나의 완결된 이야기 흐름 |
| 7 | **제목↔본문 정합** | 제목과 내용 불일치 | 부분 | 섹션의 약속과 내용 정확히 일치 |
| 8 | **인사이트 깊이 (So-What)** | 소스 요약·사실 나열(L1) | 의미 해석까지(L2) | 2차 효과·행동 함의(L3~L4) + 반론 1개 이상 처리 |

> #8 채점 근거는 so-what.md의 사다리. KEY MESSAGE가 전부 "무엇이 있었다" 형이면 0점,
> "그래서 무엇이 달라진다"가 있으면 1점, "누가 이기고 지는가/무엇을 해야 하는가"와
> 반론 처리가 보이면 2점.

## 합격선

- **총점 ≥ 12 그리고 어떤 기준도 0점 없음** → `pass: true`
- 그 외 → `pass: false`, 0~1점 기준마다 fix 항목 생성

## judge 출력 형식

```json
{
  "pass": false,
  "score": 11,
  "summary": "KEY MESSAGE 약함, §3 근거 부족, §2 인사이트 L1 수준",
  "fixes": [
    {"type": "JUDGE_KEYMSG", "loc": "§1",
     "detail": "KEY MESSAGE가 사실 나열에 그침",
     "fix": "'~로 시장이 재편되고 있음' 형태의 통찰문으로 교체"},
    {"type": "JUDGE_INSIGHT", "loc": "§2",
     "detail": "사실 요약만 있고 2차 효과 분석 없음",
     "fix": "So-What L3: 수혜/피해 주체와 행동 함의 단락 추가"}
  ]
}
```

## 루프 안에서의 위치

```
검증(claims) → 문형·표기 점검 → judge(이 루브릭) → pass 판정
pass=false → fixes만 패치 → 재채점 (상한 3회) → 초과 시 NEEDS_REVIEW로 사람에게
```

재시도마다 **fixes에 적힌 부분만** 고친다. 전체 재작성은 goal drift를 부른다.
