# style-rules.md — 문형·표기 규율 v0.1

> 목적: 사실과 의견이 문장 형태에서부터 구분되고, 모든 수치가 표찰(출처·비교축·추정)을
> 달고 있게 한다. 형식은 취향이 아니라 검증 가능성의 문제다.

## 1. 사실 ↔ 해석의 문형 분리 (최우선 규칙)

| 구분 | 문형 | 예시 |
|---|---|---|
| 사실 (verified claim) | "~임 / ~함 / ~달성함" | "매출 3.2조 원을 기록함 (YoY +18%)" |
| 회사·기관의 발표 | "~밝힘 / ~발표함" | "동사는 2027년 흑자 전환을 밝힘" |
| 분석자의 해석 | "~로 해석됨 / ~로 판단됨 / ~보임" | "구독 전환이 방어력을 높인 것으로 해석됨" |
| 전망·가능성 | "~할 가능성이 큼 (조건문)" | "X가 유지된다면 ~할 가능성이 큼" |
| 추정 수치 | 수치 + `추정`(KR) / `est.`(EN) | "2030년 500억 달러(추정, CAGR 45% 외삽)" |

혼용 금지: 해석·전망을 사실 문형("~이다/~임")으로 단정하는 순간 rubric #5(객관성)와
claims 게이트에서 걸린다.

## 2. 수치의 3중 표찰

본문의 모든 유의미 수치는 세 가지를 동반한다:

1. **출처** — claims.json의 source와 정합, 수치 밀집부에 Source 표기
2. **비교축** — YoY / 경쟁사 대비 / 시장평균 대비 중 1개
3. **문형 표찰** — verified는 사실 문형, estimate는 `추정` 표기

## 3. 과장 배제

"혁신적", "놀라운", "압도적", "게임체인저" 류의 평가 형용사는 쓰지 않는다.
평가는 수치와 비교축이 대신한다. (rubric #5)

## 4. 보고서 산문체 (요청 시 적용)

격식 보고서로 다듬을 때의 기본값 — 신동형 인사이트 analyst 산문체:

- 본문은 "입니다/합니다"체(또는 조직 관례의 "~함"체)로 **3~4단락 완결 산문**
- 개조식·bullet 나열 금지 — 나열이 필요하면 "①, ②, ③"을 문장 안에 녹인다
- 한 단락 = 하나의 완결된 주장 + 근거 + 함의
- 비교 데이터는 표, 프로세스·구조는 다이어그램으로 분리하고 본문은 서사에 집중
- 한국어 인용부호는 「단어」 형식

## 5. 다국어 소스 표기 (해당 시)

- 한글 문서: 본문 100% 한글. 고유명사 첫 등장만 `한글(原文)` — 예: `바이두(百度)`.
  이후 재등장은 한글 전용. 독립 한자·가나 토큰 금지.
- 영문 문서: 본문 100% English. 첫 등장만 `English (Pinyin, 原文)` —
  예: `Baidu (Bǎidù, 百度)`. 이후 English 전용.
- 용어 사전(Glossary)을 먼저 고정하고, 재등장 열만 본문에 쓴다.

## 6. 문서 구조 정합

- 목차(TOC)·소제목이 있으면 본문 라벨과 **1:1 일치** — 제목이 약속한 내용이 본문에 있어야 한다 (rubric #7).
- Executive Summary를 둘 경우 4파트: Key Message / 배경 / 핵심 구조 흐름 / 전망.
