# {대상} {단계} 그림 담당 브리프 (FIG)

> 이 파일은 뼈대임. 사용자가 MD 토의본을 확인한 뒤 오케스트레이터가 `{ }` 를 채워 작업 폴더에 `BRIEF_FIG.md` 로 둠
> 그림 담당에게는 「`BRIEF_FIG.md` 를 처음부터 끝까지 읽고 그대로 따를 것」 한 줄만 줌
> 그림은 Word 와 덱이 함께 씀. 그래서 원고 담당, 덱 담당보다 먼저 시작하고 끝나면 완료 표시를 남김

## 0. 그릴 것

| 파일 | 내용 | 원고(MD 절, 채택값) | 쓰는 곳 |
|---|---|---|---|
| `figs/cover.png` | {표지 그림 : 전체를 한 장으로. 예) 네 축의 핵심 수치를 이은 흐름} | {§0 셈 줄} | Word 표지, 덱 요약 |
| `figs/fig_{이름}.png` | {예) 시간대별 비중 가로 막대} | {§1 표 2} | Word 1.2, 덱 P1 |
| `figs/fig_{이름}.png` | {예) 부위별 건수 가로 막대} | {§2 표 3} | Word 2.2, 덱 P2 |

## 1. 규격

- 만드는 법 : HTML/SVG 를 Playwright(chromium)로 찍어 PNG 로 저장. 다른 그리기 도구를 써도 되지만 결과 규격은 같아야 함
- 크기 : 폭 2000px, 세로는 가로의 0.45~0.75 배. 흰 바탕
- 글꼴 : 'Noto Sans CJK KR', 'Noto Sans KR', 'NanumGothic', 'Malgun Gothic', sans-serif 순. 본문 글자 24px 이상, 큰 수치 32px 이상
- 그림 안에 제목과 출처 줄을 넣지 않음(Word 캡션, 덱 헤드라인과 출처 줄이 대신함)
- 숫자는 MD 채택값 그대로. 렌더 전에 그 숫자가 MD 에 있는지 확인하고, 계산한 값은 MD 에 식이 있는 것만 씀
- 색 의미는 덱과 같게 고정 : {예) 강조 진빨강 #A31D1D, 기준 네이비 #1A3A6B, 미확인 회색 #8A8A8A, 보조 #BDBDBD}. 색만으로 뜻을 나누지 말고 라벨을 함께 둠
- 줄표(U+2014), 과장 표현, 현황 단계의 평가어를 그림 글자에도 쓰지 않음

## 2. 순서

1. 그림 목록과 각 그림의 숫자를 MD 에서 뽑아 `figs/figs_plan.md` 에 적음(파일, 숫자, MD 위치)
2. 렌더 → `figs/*.png`
3. PNG 를 한 장씩 Read 로 열어 글자 잘림, 겹침, 빈 공간, 숫자를 확인함
4. 크기 기록 : `figs/imgmeta.json` 에 `{"파일": {"w": 2000, "h": 1200}}` (build_docx.js 는 PNG 헤더에서 크기를 직접 읽으므로 이 파일은 덱 배치와 검토용)
5. 완료 표시 : 빈 파일 `figs/_DONE` 을 만듦. 덱 담당은 이 파일이 생긴 뒤 그림 쪽을 렌더함

## 3. 최종 메시지

- 그림 경로와 크기 목록
- 그림마다 들어간 숫자와 MD 위치
- 눈으로 확인한 결과 한 줄
