# {대상} {단계} MD 토의본 : 통합 브리프 (블록 작성 B1~Bn)

> 이 파일은 뼈대임. 오케스트레이터가 조사(P2)와 2차 검증(P3)이 끝난 뒤 `{ }` 를 채워 작업 폴더에 `INTEG_BRIEF.md` 로 둠
> 블록 작성 에이전트에게는 「`INTEG_BRIEF.md` 를 처음부터 끝까지 읽고 그대로 따를 것. 담당은 B{n}」 한 줄만 줌
> 산출 : `{대상}_{시리즈}_{단계}_v0.1.md` (토의본). 사용자가 확인하기 전에는 Word 나 덱을 만들지 않음

## 0. 이번 토의본의 자리

- 단계 : {현황 / 분석 / 진단 / 제언}. 이 단계에서 하지 않는 것 : {예) 현황 단계는 판정, 평가, 제언, 점수 없음}
- 독자 : {예) 의뢰 부서 담당자. 원문을 다시 찾아볼 시간이 없는 사람}
- 확인받을 것 : 끝의 토의 안건(번호, 잠정안 포함)

## 1. 고정 용어

블록마다 다르게 쓰면 통합 때 고치기 어려움. 아래 표기만 씀.

| 쓰는 말 | 쓰지 않는 말 | 비고 |
|---|---|---|
| {예) 공공자전거} | {예) 공유자전거, 따릉이류} | {예) 원문 제도 이름 기준} |
| {예) 정류소} | {예) 대여소, 스테이션} | |
| {예) 고장 신고} | {예) 수리 요청, 민원} | 집계 기준 문서의 말 |
| {외국 기관, 매체의 한글 표기} | | 파일 사이에서 같게 |

## 2. 채택값

2차 검증을 거친 값만 씀. 블록에서 다른 값이 보이면 쓰지 말고 오케스트레이터에게 알림.

| 항목 | 채택값 | 출처 (발행일) | 2차 검증 판정 | 비고 |
|---|---|---|---|---|
| {예) 2025년 연간 대여} | {예) 1,284,300건} | {예) 가상의 B시 교통정보센터 (2026-02-10)} | 확인 | |
| {예) 대중교통 연계 비율} | 쓰지 않음 | | 부재 유지 | 원문 미발견 |

## 3. 문체와 표기

- MD 토의본 : 명사형 종결(~임, ~음, ~함), 표 위주, 날짜 `YYYY-MM-DD`
- 사실은 「~임」, 기관 발표는 「~밝힘」, 해석은 「~로 해석됨, ~로 보임」, 전망은 조건문. 현황 단계에서는 해석 문장을 쓰지 않음
- 수치에는 비교축 하나(전년, 다른 대상, 평균)를 붙임
- 쓰지 않는 문형 : 핵심은, 결국, 이처럼, ~라는 점에서, 흥미롭게도, ~하는 것이 중요합니다, 같은 문형 반복, 짧은 단정문을 연달아 쌓기
- 쓰지 않는 것 : 장과 장을 잇는 예고·안내(「다음 장에서」 「§」), 필자 자기 해설, 줄표(U+2014), 과장 표현(lexicon.json 의 hype)
- 「」 안에는 원문 문장만. 작은따옴표 인용은 「」 로 바꿈
- 정부·기관 문서는 적힌 이름, 금액, 단계만 씀. 문서의 말과 언론·정치권의 표현을 나눠 적고, 발행 기관의 관점에 기울지 않음

## 4. 블록 배정

| 블록 | 담당 | 절 | 쓸 조사 파일 | 분량 |
|---|---|---|---|---|
| B1 | {에이전트} | {§1 ...} | {research/D1_*.md} | {표 2~3개, 단락 3~5개} |
| B2 | {에이전트} | {§2 ...} | {research/D2_*.md} | |
| B3 | {에이전트} | {§3 ...} | {research/D3_*.md} | |
| B4 | {에이전트} | {§4 ...} | {research/D4_*.md, D5_*.md} | |
| 오케스트레이터 | 직접 | §0 한 장 요약, 다음 단계로 넘기는 관찰, 확인 요청, 한계, 부록 | 전체 | |

- 블록 파일 : `md/B{n}_{절이름}.md`. 각 블록은 자기 절만 씀
- 블록마다 끝에 「이 블록의 수치」 표(값, 출처, 채택값 표의 항목 이름)를 붙임. 통합 때 claims 로 옮김

## 5. 토의본 구조

1. 머리말 : 시리즈, 기준일, 단계, 표기 범례(태그 표)
2. §0 한 장 요약 : 요약 표 + 셈 줄 10~15개
3. §1~§n 본문 블록
4. 다음 단계로 넘기는 관찰 (셈과 사실, 판정 아님)
5. 확인 요청 (결론을 바꿀 수 있는 문서)
6. 한계 : 상충, 미확인, 부재 유지
7. 토의 안건 : 번호, 질문, 잠정안. 사용자가 「잠정안대로 확정」 한 줄로 넘길 수 있게 씀
8. 부록 : 파일 지도, 조사 방법(검색 수, 열람 수, 2차 검증 판정 수), 2차 검증으로 바뀐 값, 접근하지 못한 원문

## 6. 통합 뒤 검토

- 통합본은 블록을 쓰지 않은 검토 에이전트가 `REVIEW.md` 기준으로 조사 파일과 대조함
- 검토가 확인한 오류만 고친 뒤 사용자에게 보냄. 보낸 뒤에는 답을 기다림
